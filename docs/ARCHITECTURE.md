# Architecture

## Data and control flow

```text
workflow JSON
 ├─ prepare: nominal/initial XML + displaced physical Truth XML
 ├─ simulation.native → installed npsim/DD4hep/Geant4
 ├─ digitization.native → TelescopeDigitization → installed SiliconTrackerDigi
 │   └─ immutable EventHeader + TelescopeChannels (RawTrackerHits)
 ├─ native_controller → geometry audit → fresh eicrecon reconstruction
 │   ├─ installed DD4hep/ACTS services, ActsGeometryProvider and SurfaceMap
 │   ├─ installed TrackerHitReconstruction → adapted measurement conversion
 │   ├─ telescope seed → adapted CKF wrapper → installed numerical CKF/Navigator
 │   └─ installed ActsToTracks + native TrackState observer/Mille writer
 ├─ actual-surface finite differences → official Mille inspection/Pede
 ├─ independent information/solver checks → physical XML Geometry Correction
 │   └─ fresh Geometry reload and reconstruction of identical RawHits
 └─ checkpoints → unapproved candidate → JSON/Markdown/ROOT report
```

The Controller never accepts Truth Geometry as an inference input. Preparation
and Simulation use Truth; later physical-pose/Hit comparisons are offline
validation only. The native pipeline does not reinterpret the historical +Z
telescope's channels as +X data.

## Official components and local adaptations

| Responsibility | Implementation |
| --- | --- |
| Transport | Installed `npsim`, DD4hep and Geant4; native Python invocation/provenance adapter |
| Detector construction | Installed `DD4hep_SiTrackerBarrel`; local XML preparation and `BarrelMetadata.cc` describe seven real radial planes |
| Geometry conversion | Installed EICrecon Geometry services and `ActsGeometryProvider`, with actual `convertDD4hepDetector`, `TrackingGeometry` and `SurfaceMap` |
| Digitization | Installed `SiliconTrackerDigi_factory`, registered for local SiMAPS/MPGD/AC-LGAD readouts by `TelescopeDigitization.cc` |
| Hit Reconstruction | Installed `TrackerHitReconstruction_factory` converts immutable CellIDs/channels using the current Geometry |
| Measurements | Copied/adapted official `TrackerMeasurementFromHits`: actual VolumeContext/SurfaceMap association and sensor-axis covariance projection |
| Seed | Local `TelescopeSeed`: first/last hits and the validated outward 1 GeV electron prior |
| Tracking | Adapted official CKF wrapper delegates to installed numerical CKF, Navigator, filtering/smoothing; installed `ActsToTracks` serializes results |
| Alignment equations | Local `NativeMilleModel` and `TelescopeMille` observe actual native states/surfaces and write through the official Mille library |
| Global solve | Official external Pede, with retained explicit labels/steering and independent local profiling/Schur checks |
| Geometry Correction | Existing Global translation and finite left-composed SO(3) implementation, actual reload, identity/physical checks |
| Orchestration | Local Python workflow and bounded Calibration Controller with immutable inputs, stages, locks and checkpoints |

There is no replacement Geometry provider, Navigator, numerical ACTS fitter or
alignment solver. The exact nine copied official source files, original hashes
and local patches are retained in
`localDetEICrecon/experimental/telescope/provenance.json` and `upstream_diffs/`.
The directory's `experimental` name reflects the explicit research scope, not
an alternative production provider.

Removing them as apparent tests would break compilation or the Controller.
The retained/excluded inventory identifies these dependencies explicitly.

import/include/target relationships and dynamic configuration resources.

## Alignment and calibration boundary

Alignment estimates sensor poses from residual equations with four local
straight-line parameters per track and configured shared global parameters.
Calibration controls when to reconstruct, solve, validate and write another
candidate Geometry. It adds no alignment information and does not make
successive fits on the same RawHits independent experiments.

Each iteration launches fresh reconstruction with a new XML; the original Raw
ROOT bytes and channel payload remain unchanged. Checkpoints bind parent/child
Geometry, complete artifacts, actual library/source identities and accepted
track identities. Physical Geometry, finite differences, rank, associations and
solver agreement must pass before a candidate can be evaluated. The final
candidate remains unapproved; this package never activates production Geometry.

The existing scopes are bounded Y/SO(3) selections. They do not demonstrate a
fully unconstrained six-DOF fit of every sensor. Geant4 material transport and
the zero-field, material-free ACTS/Pede model remain distinct.

`localDetEICrecon/alignment/src/BeamTestMilleWriter.{cc,h}` and
`localDetEICrecon/alignment/src/TiltMeasurementModel.h` remain solely for
the independent native-versus-legacy mathematical comparison. They do not
restore the old +Z plugin/fitter or its data/Controller interface.
